### 3.2 ASReview 式主动筛选（本轮重点）

**范围**：现有 PRISMA 筛选页的标题/摘要候选排序；不做完整 ASReview 工作台。

**实现**：

- 纯排序器 `backend/app/knowledge/services/screening_priority.py`
  - TF-IDF `char_wb` 2–4 n-gram（中英文）+ LogisticRegression；
  - `random_state=42`，同分保持输入顺序，不返回概率；
  - 算法版本 `tfidf-char-logreg-v1`。
- `ScreeningRepository.list_decisions_for_task()` 单次任务级查询，避免 N+1；
- `ScreeningService.priority()` 聚合任务全员标签与候选；
- `GET /api/v1/screening/priority` 只读 API，异常映射 503；
- 前端默认关闭的“智能排序”开关、推荐徽标、阶段过滤禁用、决策后刷新；
- **无迁移、无模型持久化、不自动纳入/排除、不改 PRISMA 计数**。

标签规则：

- 任一 `include` → 正样本；
- 无 `include` 且有 `exclude` → 负样本；
- 只有 `maybe` → 忽略；
- 候选 = `title_abstract` 且任务内该阶段无任何决策。

## 8. 追加（同日晚）：Supabase 迁移已上线

向量库与整套业务库已迁到 **Supabase PostgreSQL 17.11 + pgvector 0.8.2**：
`RAG__VECTOR_BACKEND=pgvector`，`DATABASE__URL` 指向 `aws-0-eu-west-1.pooler.supabase.com:6543`。

- **验收**：`/health/ready` → ready（database/vector ok，无 chroma 键）；demo 登录 + 检索 200 且有结果；
  id 级一致性巡检 `consistent=true`（28341/28341，缺失 0 / 孤儿 0）；
  库大小 253 MB（500 MB 档余量约 247 MB）。
- **回滚**（分钟级）：服务器 `.env.bak-supabase-20261103-182904` 覆盖回 `.env` →
  `docker compose up -d backend`（chroma + 本地库，均未删除）；
  dump 备份 `~/maa-final-20261103.dump`。
- **本轮新增的运维坑**（全部已修并有回归测试）：pgvector `atttypmod` 就是维度（不减 4）；
  pooler 会话 `search_path` 为空（表名必须限定 schema）；asyncpg 两个语句缓存参数的
  传法（方言层走 URL 查询串、asyncpg 层走 connect_args 且必须 int）；
  chroma 镜像无 pgvector 时迁移只告警跳过；国内→eu-west-1 建连 6~8s、长事务会被断。
  详见 [supabase-migration.md](supabase-migration.md) §8。
- **后续观察项**：Supabase 免费档闲置会 pause（演示前预热）；30 天内保留 Chroma 卷与本地库；
  观察期无回归后再把 `RAG__VECTOR_BACKEND` 默认值改为 `pgvector` 并移除 Chroma。
- **追加（2026-11-04）：迁移后页面变慢的根因与修复**。`/tasks` 实测 34s（前端 15s 超时）：
  SQL 服务端总共 44ms，慢的全是**每条 SQL ~300ms 的网络往返**（服务器→eu-west-1）；
  旧任务列表有 N+1（每任务补 2 条查询，20 任务 ≈ 90 条）。已修（`79d1b60`）：
  列表改**单条**汇总查询，整页 1 条 SELECT，实测 **5.1s**。
  **换区域实测（2026-11-04）**：已迁到新加坡项目（`eowgihkicleusmvvoxle`），
  数据一致（28341/28341，缺失/孤儿 0，库 253 MB），但只快了 ~15%（`/tasks` 5.0s→**4.2s**）。
  原因是瓶颈不在地域而在**这台服务器的国际出口**：到新加坡仍是 **0.48s/次数据库往返**、
  TLS 握手 1.9s（到 github 也要 2.0s）。结论：应用层继续压往返收益有限，
  要真正变快只能①后端起在近邻云主机 ②业务库回到本地 Postgres（Supabase 作备份）。
  旧爱尔兰项目待用户手动删除；回滚点 `.env.bak-sg-20261104-103611`。
  N+1 在本地库每次 2ms 时完全隐形——「接远程库前先跑一遍 pg_stat_statements 数往返次数」应成为惯例。
