### 抓到的缺陷：`chunk_id` 不是 UUID（`829806e`）

**现象**：`POST /api/v1/knowledge/search` 返回的 `chunk_id` 是
`9eac9177523794ed`（16 位 hex，Chroma 内部 id），不是 SQLite `doc_chunk.id`。

**后果**：**引用无法回溯到原文** —— 用户看到一条检索结果，点不回具体段落。
而「每条证据可点回原文」正是本项目（证据约束 + 引用可追溯）的核心能力。

**根因**：端点调的是 `service.search()`（直接返回索引层结果，id 未映射），
正确入口是 `service.search_for_context()` —— 内部走 `_attach_storage_ids()`，
按 `VectorIndex.chroma_id` 把索引 id 换成 `DocChunk.id` / `KnowledgeDoc.id`。

**为什么单测没抓到**：既有测试断言了「有结果」「数量对」，但**没断言 id 的形态**。
16 位 hex 和 UUID 在「有没有结果」这个维度上完全一样。

## 巡检后发现的深层缺陷：向量库 id 级漂移（`4e4e02c`）

清理巡检数据后，一致性检查报「孤儿 1」。追查下去发现是**两个缺陷叠加**：

### 缺陷 A：`reindex` 没同步 `vector_index.chroma_id`

上一轮（`675ee41`）的 `reindex_from_chunks` 用 `DocChunk.id`（UUID）作为
Chroma id 写入，但**没更新 `vector_index.chroma_id`** —— 表里仍是建库时
生成的 16 位 hex。

服务器实测：

| 项 | 值 |
| --- | --- |
| Chroma 实际 id | UUID（28344 条） |
| `vector_index.chroma_id` | 16 位 hex（28344 条） |
| **交集** | **0** |

**为什么检索还能工作**：`_attach_storage_ids` 里「结果 id 已是 UUID →
原样保留」，恰好绕过了映射表。所以这条链路的缺陷被**掩盖**了 ——
如果不是做 id 级校验，永远不会发现。

### 缺陷 B：一致性校验只比数量（**更严重**）

我上一轮写的 `check_vector_consistency` 只比对「分块数」与「向量库条数」。
数量完全相等（28344 vs 28344）→ 报「一致」。

**数量对得上，数据全错。** 这是校验工具最危险的失败模式：
它不仅没抓到缺陷，还给出了「一切正常」的假信号。

### 修法

1. `reindex` 每批写入后同步 `update vector_index.chroma_id = chunk_id`，
   最后统一提交；
2. `check_vector_consistency` 默认 `verify_ids=True`：拉全量 id 做集合比对
   （28344 条约 2-5 秒），报告新增 `missing_ids` / `orphan_ids`（各限 20 条样本）；
3. `VectorStore.list_ids()` 新增（`size` 只给数量）；
4. `--skip-ids` 保留快速探活能力（明确标注会漏检）。

### 验证

| 步骤 | 结果 |
| --- | --- |
| 修复前的 id 级校验 | `missing=28344 orphan=28345`（交集 0） |
| reindex（含同步） | 28344/28344，0 失败 |
| 同步后校验 | `missing=0`，孤儿 1（巡检残留） |
| 删孤儿后 | **`vector_consistency_ok chunks=28344 vectors=28344 ids_verified=True`** |
| 检索 | `vector_hits=30` → `results=5`，chunk_id 为 UUID |

### 测试诚实性（两组回退验证）

| 回退项 | 结果 |
| --- | --- |
| 删掉 reindex 里的同步调用 | `test_reindex_vector_index_sync` 全红 ✅ |
| `consistent` 改回「只比数量」 | `TestIdLevelDrift` 全红 ✅ |

新增 9 条测试（同步 3 + id 级校验 6）。

### 教训

**校验工具本身也要被校验。** 「数量相等」是个很弱的断言 ——
它抓得住「少了一半」，抓不住「全错了但数量一样」。
写校验时要想「什么情况下这个检查会给出假绿」，并针对那个情况加断言。
