## 3.8 引用库遗留三项（`8cfed9b`，已完成）

### 取证：引用库有文献，却没证据

上一轮引用库任务 `completed`、检索节点 6/6 artifacts 来自引用库，
但 `evidence_pool` 是空的。根因是**两条线互不相干**：

```
search 节点   → self._source.search()              → artifacts
extract/write → LiteratureContextBuilder.build()   → evidence
                        ↓
        knowledge.search_for_context(user_id, query)   ← 只查知识库向量索引
```

写作 Agent 在没有任何证据的情况下生成内容。

### 交付

`Evidence.kind`（`excerpt`/`metadata`）+ `metadata_evidence()` +
`prepare_node` 合并两类证据 + `normalize_doi()` 去重合并 +
`PATCH` 条目编辑 + 前端编辑表单与合并计数。

**元数据证据不含编造摘要** —— CSL 条目没有摘要字段，`abstract=""` 是故意的。
元数据证据只能支撑「存在这样一篇文献」，不能支撑「作者指出……」。

### 两个「假绿」（测试全过、产品不工作）

#### 假绿 1：测试夹具用了产品不产生的形状

第一版读 `dependency_outputs[...]['artifacts']`（顶层），测试夹具也传扁平形状
→ **9 条全绿**。但 `scheduler` 存的是 `nr.output`，形状是
`{result, status, execution_result: {artifacts: [...]}}` —— artifacts 在
`execution_result` **里面**。真实任务 metadata = 0 才暴露。

**这是 AGENTS §5 #16 在同一会话里犯的第二次**（第一次是 token 统计）。
已升级为 §5 #33：**写提取逻辑前先 `print(json.dumps(真实载荷, indent=2))`**。

诚实性验证：恢复「只认顶层」→ **10 条变红**（含 2 条形状契约测试）。

#### 假绿 2：新证据类型撞上既有校验器

形状修好后真实任务 `waiting_human`：

```
✗ evidence_ids_valid: 证据标识缺失: ['[E1]', '[E2]']
```

校验器要求每条证据有 `doc_id` + `chunk_id`，元数据证据**按设计没有**。
**不能填假 UUID 过检查**（那让「可回溯」变成假话）。修法：检查只对
