### 3.1 用量看板（已完成，`b5bf912`）

交接时排在风险第一位是对的，但**实际发现的问题比「版式不好」严重得多**：

- **后端从来没记过 token 用量**：`sum_actual_tokens` 读顶层字段，生产载荷是嵌套的
  → `task.used_tokens` 全库恒为 0 → 看板「累计 token」永远 0，
  **且配额结算每次都退满（用户白嫖算力）**；
- 状态分布漏 `waiting_approval` → 「总数 27 / 分布 26」，差值不可见；
- 成功率没有分母；最近任务只有 8 位 UUID；
- 回填脚本把 28 个任务的 `updated_at` 刷掉（耗时显示 9708 分）——**已恢复**；
- 任务行 `<li @click>` 键盘不可达——已改 `<button>`。

已回填历史用量 169372 token 并独立 SQL 核对一致。设计记录见 §4.14。

### 3.3 引用样式页（已完成，`e6bd1f7`）

交接时认为「展示型，风险低」，实际缺陷是**这一页最该展示的东西没有展示**：

- **完全没有预览**（`HAS_PREVIEW_WORD=false`，样式行不可点不可展开）。
  而 `gbt7714-2025-numeric` 与 `gbt7714-2015-numeric` 的元信息**完全相同**
  （`META_DISTINCT = 5/6`），用户无法区分 —— 两者真实输出差异明显
  （2015 版无 `[J]` 类型标识）；
- **删除无确认**（后端会 unlink 磁盘文件）。

新增 `GET /citation-styles/previews`，复用导出用的 `CitationRenderer` 渲染
2 条固定样例（中英各一条）。实测 `AFTER_DISTINCT = 6/6`，`warnings = 0`。

设计记录见 §4.16。

### 3.4 下一个页面（Word 模板页）的开局提醒

前三页的真缺陷都不是版式，而是**「页面上的信息不足以完成任务」**。
Word 模板页建议先查：

1. **占位符列表是否来自真实解析**（而不是硬编码一份清单）；
2. **渲染下载闭环**：上传模板 → 填占位符 → 下载，产物里占位符**是否真的被替换**
   （下载一个文件打开看，不能只看接口 200）；
3. 模板里**缺失占位符**时的行为（静默留空？还是报错？留空会让用户以为成功了）；
4. 上传 `.docm`/宏/OLE/zip 炸弹的拒绝消息是否可读。

**每个页面的工作方式**（照第六、七、八阶段的做法）：

1. **先量真实数据** → 从接口与页面的差异里找**真实缺陷**（不是版式偏好）
2. 写**失败测试**复现（断言要覆盖「这个值能不能用」，不只「格式合不合法」）
3. 实现 → 绿
4. **再量数值 + 结构化取证**验证（修复前后逐项对照）
5. 诚实性验证：回退修复 → 必须变红（**用 `edit` 精确替换**，不用 `-replace`）
6. 全套门禁（**前端必须跑 `vue-tsc -b`**，见 AGENTS §5 #18）→ 提交 → 部署 →
   真实浏览器验证 → 文档 → 推送
7. **探针脚本不要 `sys.path.insert` 项目根**（AGENTS §5 #25）；
   涉及 CSL 渲染时断言 `warnings` 为空（§5 #26）
