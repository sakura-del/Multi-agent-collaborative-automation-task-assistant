## 7. 必须知道的坑（按踩到的顺序，全部真实踩过）

1. **后端部署必须在 `deploy/ecs` 目录 build**。在 `/opt/veripaper` 根目录跑
   `docker compose build backend` 会产出 `multi-agent-assistant-backend`（另一个项目名），
   生产用的仍是旧镜像 —— 白构建一次。
2. **SSH 长命令会被缓冲导致断连**。`docker compose build | tail -n 8` 在构建期间无输出，
   SSH 约 60 秒被对端断开。做法：`setsid nohup cmd > /tmp/log 2>&1 &`，再用短命令轮询日志。
3. **前端变量必须在构建前保存**。Pages 先连 Git 触发构建、后加环境变量，产物会缺
   `VITE_API_BASE_URL` → 前端退化为相对路径 `/api/v1` → 请求打到静态站拿到 HTML，
   整体不可用。修法：API 重试部署（`POST .../deployments/{id}/retry`）。
4. **Secret 类型变量在 API 里读不到明文**（`GET projects` 返回空字符串是正常的）。
   判断变量是否生效只能查**构建产物**：`curl /assets/index-*.js`，搜索 `api.veripaper.me`。
5. **限流按代理 IP 计数**：`RATE_LIMIT__TRUST_PROXY=false`，`request.client.host` 恒为
   nginx 容器 IP（实测 key `ratelimit:3600:auth_register:ip:172.18.0.5`）。注册 5 次/小时
   是**全局**配额，做接口测试会耗尽全体额度 → 测试后必须
   `docker exec vp-redis redis-cli --scan --pattern 'ratelimit:*' | xargs -r redis-cli DEL`。
6. **Cloudflare GitHub App 的 slug 是 `cloudflare-workers-and-pages`**（不是
   `cloudflare-pages`，后者 404）。只能在 Dashboard 或该 App 页授权。
7. **PowerShell 三个反复踩的坑**：中文读写乱码（用 read/write 工具或 Python 脚本）；
   `$home` 等只读变量赋值报错（换变量名）；SSH 一行命令带引号/glob 被远端拆坏（写 `.sh`）。
8. **模板功能必须走 `validate_template_bytes`**：用户上传的 docx 由 docxtpl（Jinja2）渲染，
   历史上有 SSTI → RCE（已修，见 #9）。新增模板相关入口时不要绕过校验，渲染必须用
   `SandboxedEnvironment`。
9. 其余历史坑（CRLF、`.env` 白名单、pg_dump 版本、pgvector schema 等）见
   `ecs-deployment.md` §6 与旧 handoff。
