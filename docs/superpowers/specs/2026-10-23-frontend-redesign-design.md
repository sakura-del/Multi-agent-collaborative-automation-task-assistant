## 1. 背景与诊断

用户要求「把页面优化一下，前端重新设计」，并指定风格参考
<https://asharca.github.io/ui/>（beUI）。

先用 Playwright 截取服务器真实页面（6 个核心页 + 移动端），确认现状问题：

### 问题 1：任务列表是「同质化墙」

20 行里有 19 行标题几乎一样（`检索增强生成评估方法综述（…复验 #3）`），
唯一区分靠括号后缀，而它被排成普通正文。

### 问题 2：进度条说谎

`taskProgress(status)` 是**从状态映射的百分比**，不是真实进度：

```ts
failed: 100,      // ← 失败也显示 100% 满格蓝
completed: 100,
```

视觉上「失败」和「完成」的进度条**一模一样**。这列几乎不传递信息。

### 问题 3：侧栏 9 项同权重平铺

`任务 / 知识库 / 引用样式 / Word 模板 / 导入文献 / 团队 / 用量 / API Key / 我的套餐`

「任务」是每天用的，「API Key」配一次就不动 —— 平铺让日常路径淹没在设置项里。

### 问题 4：登录页没有产品身份

白底一张卡片，看不出这是「生成即合规、引用可核验」的学术工具。

### 问题 5：整体「装了 shadcn 但没做设计」

Nova 中性基调没错（AGENTS §6.5 要求安静、不抢注意力），但**没有层次**：
标题、正文、表格、卡片几乎同一灰度，视线没有落点。

## 2. 设计语言：beUI 的三条特征

参考 beUI 的**视觉语言**，不取其代码 —— 它是 React + Framer Motion，
本项目是 Vue，动效统一走 motion-v（AGENTS §6.5.2）。

从渲染后的页面提取真实 token（`extract_tokens` 脚本，见执行记录）：

| 特征 | beUI 取值 | 本项目落地 |
| --- | --- | --- |
| **6% 发丝边框** | `oklch(15% 0 0 / .06)` | 同（`--border`），另留 `--border-strong` 12% 用于需要明确分割处 |
| **卡片略亮于底色** | 底 99% / 卡片 97% | 底 98.5% / 卡片 100%（靠「更白」产生层次，不靠阴影） |
| **高对比文字 + 低对比线条** | 文字 15% / 线条 6% | 同 |
| 主色 | `#0285f7` 亮蓝 | `oklch(0.62 0.19 250)`（比旧 Nova 沉蓝更醒目） |
| 徽标 | 药丸形 + 淡色底 | 沿用既有 `success/warning/destructive` 淡底变体 |
| 导航 | 微缩大写分组标签 | 同（`text-[11px] uppercase tracking-wider`） |

## 3. 已交付内容

### 3.1 tokens（`src/assets/main.css`）

| 项 | 旧 | 新 |
| --- | --- | --- |
| `--border` | `oklch(0.922 0 0)` 实色灰 | `oklch(0.15 0 0 / 6%)` 发丝线 |
| `--background` | `oklch(1 0 0)` | `oklch(0.985 0 0)` |
| `--card` | 与底同白 | `oklch(1 0 0)`（**更亮**，反常规产生层次） |
| `--primary` | `oklch(0.55 0.2 255)` | `oklch(0.62 0.19 250)` |
| `--radius` | `0.5rem` | `0.625rem` |
| 新增 | — | `--border-strong` / `--accent` / `--surface-brand` / `--shadow-raised` |
| `body` | — | `font-variant-numeric: tabular-nums`（表格时间不跳动） |

深色模式同步调整（beUI 深色边框用白 6%）。

### 3.2 侧栏（`src/layouts/AppLayout.vue`）

9 项平铺 → **4 组**：

```
（无标题）  任务 · 知识库
素材        引用样式 · Word 模板 · 导入文献
协作        团队 · 用量
设置        API Key · 我的套餐
```

第一组省掉标题（避免视觉噪音）；「设置」沉到最后，因为它是配一次就不动的。

底部补「用户名 + 邮箱」+ 分隔线。

**窄屏**：折成单行横向滚动导航（`max-md:flex-nowrap` + `overflow-x-auto`），
实测高度 **36px**（旧版折 3 行约 150px）。分组标题窄屏隐藏 —— 横向滚动条里
放不下，优先保证「一眼看到全部入口」。登出按钮跟在导航行之后单独一行右对齐
（早期版本用绝对定位，结果压在滚动中的导航项上，截图实测发现后修正）。

### 3.3 登录页（`src/views/LoginView.vue`）

双栏：左侧品牌面板（`--surface-brand` 淡蓝分区）+ 右侧表单。

左侧内容：

- 价值主张：**生成即合规，引用可核验**
- 三个能力点（**都对应真实功能，不是营销词**）：
  - 证据约束 —— 每条结论都能回溯到原文段落
  - 引用可核验 —— GB/T 7714—2025，支持 CrossRef 真实性校验
  - 人机协同 —— 规划先确认，导师可逐段批注

窄屏（`< lg`）隐藏左栏，改为表单上方紧凑品牌行。

## 4. 测试与验证

### 4.1 新增测试（`src/layouts/AppLayout.test.ts`，8 条）

锁的是**导航结构与 E2E 契约**，不是版式细节：

- `app-nav__links` 类名必须保留（`e2e/phase1-pages.spec.ts` 的 resetScroll 依赖）
- 9 个目的地一个都不能少
- 分组顺序（设置置末）
- 当前项用 `aria-current="page"` 断言（不用 `router-link-active` 类 —— 那是版式实现细节）
- 登录页保留 `#account` / `#password` / `[data-test="forgot-password"]`（自动化脚本依赖）

## 5. 待做：任务列表页内部重设计

**这是本阶段故意留出的第二步**（用户确认「先做全局层，任务列表稍后」）。

| 问题 | 计划改法 |
| --- | --- |
| 同质化标题墙 | 标题**主行**只显示主题，括号里的后缀（`Issue #6 复验 #3`）降为**次级灰字**同排 —— 用户已确认此方案 |
| 进度条说谎（失败=100% 满格蓝） | **删掉进度条**，改状态徽标 + 图标（✓ / ✕）；进行中才显示细进度条 |
| 没有汇总 | 顶部 4 个统计卡：**待我确认**（`waiting_approval` + `waiting_human`，唯一需要用户行动的）/ 进行中 / 已完成 / 全部 |
| 没有筛选 | 状态筛选分段控件（带计数），「待我确认」默认高亮 |
| 20 个「打开」按钮 | 整行可点击 + hover 浮现箭头 |
| 无搜索 | 标题模糊搜索（纯前端） |

### 为什么先做全局层

1. **风险可控**：tokens 与布局是全站共享的，先验证它们不会破坏既有 24 个页面；
2. **体感最大**：侧栏 + 登录页是每个用户每次进入都看到的；
3. **为列表页铺路**：列表页要用的 `accent` / `border-strong` / `shadow-raised`
   已经在 token 层就位。
