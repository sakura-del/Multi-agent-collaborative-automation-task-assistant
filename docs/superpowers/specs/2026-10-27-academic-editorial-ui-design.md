# 学术编辑感 · 前端视觉升级方案（概念稿）

> 日期：2026-10-27  
> 状态：方向已选「学术编辑感」，概念稿待用户确认；**尚未修改生产代码，尚未提交 Git**  
> 范围：登录页、全局工作台外壳、任务列表、任务详情/综述结果；其余页面在方向确认后沿用同一语言。

## 1. 结论

当前前端可以明显做得更高级，但**不需要推倒重来**。

现有 Vue 3 + Tailwind CSS v4 + shadcn-vue + Lucide + motion-v 技术栈已经足够，上一轮 beUI 改造也解决了导航分组、状态表达、Markdown 渲染、引用核验等基础问题。此次应在既有体系上做一次「视觉层级 + 产品辨识度 + 阅读体验」升级，而不是更换框架或再引入一套组件库。

推荐方向：**学术编辑感（Academic Editorial）**。核心记忆点不是渐变和装饰，而是「论文纸页 + 可回溯证据」。

## 2. 已检查材料与复用判断

- 已读取现有前端技术栈、设计 tokens、全局布局、登录页、任务列表、任务详情与结果组件。
- 已读取既有重设计文档，确认此前设计目标与测试契约，避免重复推翻已完成的改造。
- 已通过 Playwright 登录服务器真实页面，截取 1440×1000 的登录页与任务列表；浏览器控制台无错误，页面无横向溢出。
- 已复用现有真实功能作为设计内容：证据约束、引用核验、GB/T 7714—2025、Markdown/DOCX 导出、规划确认、导师批注。

**为什么不另起一套**：现有技术栈、组件与数据契约完整，另起一套只会增加迁移和回归成本；本次提升主要来自排版、色彩、空间与信息组织，而不是新依赖。

## 3. 现状诊断

### 3.1 登录页

现状已经具备双栏和价值说明，但仍偏「标准产品介绍 + 登录卡」：

- 标题与正文均为无衬线，缺少学术产品的编辑气质。
- 左侧大面积留白只承载文字，没有展示产品最关键的「正文—引用—证据」关系。
- 亮蓝按钮和浅蓝底色接近通用 SaaS，品牌记忆点不足。

### 3.2 任务列表

现状功能完整，但视觉仍是通用后台表格：

- 四张等宽统计卡占据首屏主要位置，和下方筛选计数重复。
- 18 行完成任务只显示一个绿色勾，虽然节省空间，但扫描时语义不够明确。
- 标题、状态、时间之间的字号与灰度差距有限，重复标题仍容易形成「列表墙」。
- 「待我确认」是最重要动作，但目前只以一张黄色统计卡表达，行动焦点还可以更集中。

### 3.3 综述结果

现有结构已经是正文 + 右栏，基础合理，但可以进一步突出核心交付物：

- 正文仍是普通卡片中的 Markdown，缺少「最终研究成稿」的纸页感。
- 引用核验、质量评分、参考文献和下载都挤在 16rem 右栏，视觉权重接近。
- 标题、正文、引用标记和证据高亮尚未形成统一的编辑排版系统。

## 4. 方向比较与选择

| 方向 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| **学术编辑感** | 贴合文献综述；长文阅读最好；能强化证据可核验的差异化 | 需要精细调整中文衬线排版与信息密度 | **用户已选择，推荐** |
| 深色研究控制台 | 科技感强，状态与 DAG 表现醒目 | 长文阅读、DOCX 心智与打印场景不一致；深色对比度成本高 | 不作为本轮方向 |
| 轻盈现代 SaaS | 实现快、亲和力高 | 容易回到常见卡片模板，产品辨识度有限 | 不采用 |

## 5. 视觉系统

### 5.1 色彩

概念稿使用以下色值；正式实现应转换并合并进现有 OKLCH tokens，**不能新增第二套并行变量**。

| 角色 | 概念色 | 用法 |
| --- | --- | --- |
| 暖纸白 | `#F5F4EF` | 页面底色，降低纯白刺眼感 |
| 纸面白 | `#FDFCF9` | 正文纸页与主要容器 |
| 墨色 | `#19231F` | 标题与正文，替代纯黑 |
| 青蓝绿 | `#236761` | 唯一品牌强调色：主按钮、引用、当前项 |
| 浅青灰 | `#E6EFEA` | 当前导航、证据高亮、核验状态 |
| 琥珀色 | `#9A682C` | 只用于「待确认」等需要行动的语义 |

原则：不使用紫蓝 AI 渐变；不大面积发光；卡片默认不靠厚阴影；用纸色、文字和细分隔线建立层次。

### 5.2 字体与排版

- **展示标题/论文正文**：`Noto Serif SC / Source Han Serif SC / Songti SC` 系统字体回退链。第一版不强制加载大型网络字体；若后续要求跨平台完全一致，再评估自托管子集。
- **导航、表单、状态和数据**：沿用现有无衬线体系，保证工作台效率。
- **数字与编号**：等宽数字，保留 `font-variant-numeric: tabular-nums`。
- 大标题收紧字距，正文增加行高；长文正文控制在约 680–760px 可读宽度，不能铺满宽屏。

### 5.3 形状与动效

- 外壳圆角 8–12px；正文纸页更克制，可用 4–12px 的非对称小圆角。
- 图标继续只用 Lucide，统一 1.7 左右的视觉线宽，不新增图标库。
- 动效继续只用 motion-v / CSS：160–240ms，小距离淡入与状态过渡；不做滚动视差和持续漂浮动画。
- 所有动效尊重 `prefers-reduced-motion`。

## 6. 三个核心页面方案

### 6.1 登录页：把差异点直接画出来

- 保留双栏与现有登录/注册交互。
- 主标题改为衬线编辑排版，品牌色由通用亮蓝改为深青蓝绿。
- 左侧新增一张「正文证据片段」视觉卡：正文引用标号、引用核验状态、GB/T 7714 信息同时出现，让用户登录前就理解产品差异。
- 右侧表单减少卡片感，放大欢迎标题和输入区层级。
- 移动端只保留紧凑品牌、标题和表单，证据卡不挤占首屏。

效果图：`docs/design/2026-10-27-premium-redesign/concept-login.png`。

### 6.2 任务页：从统计后台变成研究索引

- 四张统计卡改为一条轻量汇总带，数字仍在，但不再与筛选重复争夺注意力。
- 「待我确认」变成一个集中行动区，直接说明确认规划后才会执行。
- 完成任务恢复「✓ 已完成」的文字 + 形状，避免只靠图标猜状态。
- 主标题与括号/版本标记继续两级展示；待确认行用细色条和浅底区分，不靠整行浓黄。
- 保留现有新建、筛选、搜索、整行进入和空态能力。

效果图：`docs/design/2026-10-27-premium-redesign/concept-tasks.png`。

### 6.3 综述结果页：论文纸页 + 证据边栏

- 中间正文作为视觉主角：纸面白、衬线正文、章节编号、引用标号、克制的证据高亮。
- 右栏重新排序：引用与核验 → 质量检查 → 参考文献 → 导出与交付。
- 顶部保留返回、状态、批注、导出和四个既有 Tab；不为了美感改变任务流程。
- 桌面采用正文 + 265–300px 证据栏；窄屏改为正文优先，证据区折叠到正文后或抽屉。

效果图：`docs/design/2026-10-27-premium-redesign/concept-result.png`。

## 7. 数据真实性边界

概念稿中的正文、计数、评分、文献和日期是**视觉示例**，图片已标注「示例内容，非生产页面」。正式实现必须遵守：

1. 只使用现有 API 已返回的数据，不为效果图额外硬编码指标。
2. `reference_verification` 不存在时展示「未开启外部核验」，不能显示「6/6 均已核验」。
3. 质量评分、参考文献数、批注数、修订号均从真实快照读取；无数据时使用明确空态。
4. 不实现概念稿里的虚构页码 `01 / 12`，除非后续有真实分页数据。
5. 新增视觉内容不得伪造引用、DOI、证据片段或任务进度。

本轮推荐只做前端视觉与信息层级，**不要求修改后端接口**。

## 9. 验收方式

每一阶段报完成前都必须提供结果证据，而不是只报告代码完成：

1. Playwright 截取 1440×1000 桌面图和约 390px 宽移动图，逐张人工查看。
2. 实测关键元素 `boundingBox()`、可见数量、正文宽度与横向溢出；每次调整尺寸后重新量。
3. 覆盖真实空态、加载、失败、未核验、无评分、无参考文献等状态，不用 mock 数字冒充真实数据。
4. 跑 Vitest、`vue-tsc -b`、Vite build 与受影响 E2E；改 DOM 前先检查既有断言。
5. 对新增行为测试做回退验证：回退实现后测试必须变红；抓不住的断言删除。
6. 对比度达到 WCAG AA，键盘焦点、图标按钮名称与减少动效偏好保持有效。
