# WisPaper 蓝色编辑感 · 登录页与任务首页设计规范

> 日期：2026-10-28
> 状态：用户最终未采用该方向；两页代码已回退，不再进入后续实施。

## 1. 目标与范围

把 [WisPaper 首页](https://www.wispaper.ai/zh/home)的浅蓝空气感、胶囊控件与大圆角工作区融入现有「学术编辑感」，但保留暖纸底色、衬线标题和既有任务流程。

本批仅覆盖：

- `frontend/src/views/LoginView.vue`
- `frontend/src/views/TaskListView.vue`
- 支撑两页的设计 tokens 与既有测试/截图

明确不改：其他页面、侧栏结构、全局主色、后端接口、Pinia 数据流、任务创建/搜索/筛选业务逻辑。

## 2. 调研与复用判断

已实际用 Playwright 打开参考站，截取桌面与移动端，并读取标题、按钮和卡片计算样式。参考站的关键特征是：浅蓝环境光、粗无衬线标题、居中大搜索框、胶囊按钮和大圆角工作区预览。完整参考图位于 `docs/design/wispaper-reference/desktop.png`。

也对照了当前 Vue/Tailwind/shadcn 实现与两页测试。现有组件已足够，**不引入新框架、新依赖或第二套业务流程**。用户在三版中明确选择 **B · 蓝色编辑感**，而非完整复刻官网布局。最终概念稿为 `docs/design/wispaper-reference/blue-editorial-final.png`。

## 3. 视觉设计

### 3.1 保留与新增

| 保留 | 新增/调整 |
| --- | --- |
| 暖纸白背景与纸面白卡片 | 局部浅蓝空气感背景，不使用整页高饱和渐变 |
| 中文衬线展示标题 | 标题局部蓝色强调，正文和导航仍保持无衬线 |
| 墨色正文与既有语义状态色 | 两页专用的低饱和蓝操作色与浅蓝选中底 |
| 细分隔线、紧凑信息密度 | 更大的胶囊按钮、搜索框、证据卡和任务索引圆角 |
| 当前键盘焦点、移动布局与状态图标 | 保持足够文字对比度和清晰点击区域 |

新增 token 只表达本批视觉角色，例如 `air-background` / `air-primary` / `air-accent`，通过 `main.css` 的 `@theme` 映射使用。**不替换现有 `--primary`、`--success`、`--warning`、`--destructive`**，避免影响其他页面。Tailwind 类名必须是静态字面量，禁止动态拼接。

### 3.2 登录页

- 保留双栏：左侧价值主张与证据示例，右侧登录/注册表单。
- 标题继续使用衬线；局部文字用蓝色强调，而非改成参考站的粗黑无衬线。
- 证据卡增加浅蓝描边和大圆角，继续明确标注「示例」，不得冒充真实核验结果。
- 表单 tabs、按钮和输入区采用更柔和的圆角；保留 `#account`、`#password`、忘记密码与全部认证逻辑。
- 移动端保留紧凑品牌、标题与表单，隐藏左侧大面积品牌/证据区域。

### 3.3 任务首页

- 保留侧栏、页头、统计、待办、筛选、搜索和任务索引的既有结构。
- 页头标题仍为「研究任务」，主按钮仍为「新建综述」。
- 大搜索框直接承载当前 `data-test="task-search"`，只执行现有标题过滤。**“输入新课题”之类文案不得暗示存在第二条创建路径。**
- 新建任务仍由当前 `data-test="new-task"` 展开既有 `TaskCreateForm`。
- 汇总数字保留真实 computed counts；待办行动区继续使用 `needsUserAction`，说明同时覆盖规划确认和人工暂停。
- 任务索引圆角和卡片间距增大，但不改变行打开按钮、状态文本、进行中进度和移动端键盘操作。

## 4. 响应式与无障碍

- 桌面目标视口 1440×1000，移动目标视口约 390×844。
- 搜索框在移动端独占一行；统计允许换行；待办操作区不得被右側链接挤压。
- 长任务标题继续截断/换行，移动端打开按钮保持可聚焦且可通过 Enter 触发。
- 普通文字对比度 ≥4.5:1，焦点指示 ≥3:1；蓝色按钮使用白色文字时必须实测，不能凭色值估计。
- 不引入持续动画；若加入颜色/阴影过渡，继续使用 150–200ms 并尊重 `prefers-reduced-motion`。

## 5. 数据与测试契约

必须保留：

- 登录：`#account`、`#password`、`forgot-password`、登录/注册提交行为。
- 任务：`new-task`、`task-search`、`filter-*`、`stat-*`、`attention-needs-me`、`task-row-*`、`task-title-main/meta`、`status-icon`、`terminal-status-label` 和 `button[aria-label="打开"]`。
- 空态、筛选无结果、真实计数、待办切换、搜索大小写不敏感和详情导航。
- 现有单元测试与 E2E 的语义；装饰类变化不得被当成业务变化。

新增视觉不得伪造任务数量、进度、引用核验结果或“AI 正在思考”等状态。截图里的示例数据只用于概念稿，生产页面继续读取真实 store/API。

## 6. 验收计划

1. 先跑受影响测试基线；视觉测试锁结构契约，不锁易变的 Tailwind 装饰类。
2. 运行全量 Vitest、`vue-tsc -b`、Vite build。
3. 在正式部署上用 Playwright 截取两页的桌面/移动图，逐张人工检查并测量 `scrollWidth`、搜索框、操作按钮和任务行。
4. 重点 E2E：`m2-preview`、`m2-result-preview`；登录限流时等待窗口，不把 429 当视觉回归。
5. 对既有行为测试执行必要回退验证；纯视觉改动用生产截图和几何/对比度数据证明，不伪造“测试变红”。

## 7. 实施边界与交付

允许修改上述两页、`main.css` 中支撑它们的 tokens、相关测试和本轮设计/验收文档。不得顺手重改其他页面或实验/后端文件。

预期结果：用户能明显感受到 WisPaper 的浅蓝、胶囊与大圆角，但仍看到熟悉的暖纸衬线学术工作台；任务创建、搜索、筛选和结果访问方式完全不变。
