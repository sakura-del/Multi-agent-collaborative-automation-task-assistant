## 3. 我反复犯的错（要固化的硬约束）

### 错 1：改完就报完成，没仔细看渲染结果

阶段二、三各补 3 次和 2 次修复。典型：DAG 节点从 68px 加高到 84px 修好叠字后，
**没有重新量容器高度**，导致 5 个节点又只能看到 4 个 —— 同一个「裁切」问题
以不同原因出现两次。

> 规则：**UI 改动必须真实浏览器截图 + 量数值（可见性、元素个数）才算完成**，
> 而且**每次调整尺寸后要重新量**，不能凭推理认定「这样就好了」。

### 错 2：断言写「合法」而不是「可用」

团队工作区的中文名兜底，最初断言 slug「非空 + 匹配 `^[a-z0-9-]+$`」。
而纯中文折叠出来的 `"----"` **两条都满足** —— 把兜底逻辑删掉测试仍然绿。
诚实性验证才发现。

> 规则：**断言要覆盖「这个值能不能用」**。`"----"` 合法但不是可用标识，
> 必须断言含字母或数字。

### 错 3：为了让测试变绿而加额外触发，掩盖真实缺陷

slug 派生的旧单测写成 `setValue` 之后再 `trigger("input")` 一次。
第一次触发时 `v-model` 还没写入，派生读到旧值；第二次触发才「碰巧」正确。
真实浏览器只发一次 `input`，所以线上是坏的。

> 规则：**测试必须模拟真实调用序列（单次事件）**。加额外触发让测试通过 =
> 自己制造假测试（对应项目 AGENTS #13）。

### 错 4：改 DOM 前不 grep E2E 断言

删「打开」按钮 → `getByRole("button", { name: "打开" })` 失败；
批注改抽屉 → `getByRole("heading", { name: "导师批注" })` 失败。
两次都是自己引入的回归，只有跑 E2E 才暴露。

> 规则：**改 DOM 结构/文案前先 `grep e2e/` 该元素的选择器**，
> 并判断「这是设计变更（该改测试）还是回归（该改实现）」。

### 错 5：scratch 脚本进了提交

`verify_detail.mjs`、`kb.mjs` 这类一次性验证脚本被 `git add -A` 带进仓库，两次。

> 规则：**提交前看 `git status`**，临时脚本放 `$env:TEMP`，不要放仓库目录。

### 错 6：ssh 一行命令里用 glob

`git fetch ~/maa.bundle '+refs/heads/*:refs/remotes/win/*'` 在服务器 zsh 下报
`no matches found`。本会话踩 3 次（另两次是 grep 多词与 `(...)`）。

> 规则：**服务器操作一律写 `.sh` 文件再 `bash`**，不要塞进 ssh 一行命令。

### 错 7：PowerShell 做 UTF-8 文本往返

项目 AGENTS #1 已明令禁止，本会话仍踩（用 `python -c` 里的字符串替换才修好）。
正确做法：`edit`/`write` 工具，或写独立 Python 脚本文件。

1. 从日志发现 5 节点全完成，DAG 只画 3 个 → 推断是宽度不够

4. 复查发现**又裁切了**（4/5）→ 改容器高度

**阶段五「团队工作区」**（返工 0 次）：

1. **先截图**看现状 → 发现点创建报「请填写团队名与标识」
2. 从截图倒推根因（`fill()` 一次 input → slug 为空）
3. 写失败测试（断言 `'ab' === 'abc'` 复现逐字输入少字符）
4. 改 `watch`，绿
5. 再截图验证 → 报完成

差别不是能力，是**顺序**：先拿证据再改，而不是改完再找证据。
