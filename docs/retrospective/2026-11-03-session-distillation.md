## 3. 模型反复犯的错

### 3.1 PowerShell 解析 API JSON 数组不可靠（本次最贵的操作错误）

**现象**：部署后用 `Invoke-RestMethod` 取 `/tasks`，无论 `$tasks[0]`、`@(...)` 还是
`Select-Object -First 1`，`$first.task_id` 都把 20 个 id 拼成一个字符串，连续 3 次请求才改用 Python。

**根因**：PowerShell 对 JSON 数组的展开/成员枚举行为与预期不一致；这不是 API 缺陷。
同一个冒烟还先用了 `username` 字段，实际登录契约是 `account`，多花一轮。

**修复**：API 冒烟/数组提取一律用 Python `httpx`（或 `requests`），不再用 PowerShell 解析业务 JSON。

**已固化**：`~/.dsh/AGENTS.md` →「本机已知坑」新增一行。

### 3.2 门禁命令工作目录错误 + 未按 exit code 止损

**现象**：补边界测试后从仓库根执行：

```powershell
python -m black tests/test_screening_priority_service.py
python -m ruff check tests/...
git commit ...
```

Black 报路径不存在、Ruff 报 `E902`，但命令串联没有在失败处停止，commit 仍然执行了。
虽然测试文件实际已格式化，提交内容没错，但“红灯还提交”是危险流程。

**修复**：门禁必须在 `backend` 工作目录执行；每条检查后看 `$LASTEXITCODE`，
失败时不得继续 commit；提交前单独 `git diff --cached --check`。

**已固化**：交接文档 §6；项目 AGENTS 已有“门禁逐个跑”条目，本次是执行偏差，不新增重复规则。

### 3.3 重复相同参数的 `job_output` 轮询

**现象**：部署构建期间连续两次 `job_output(wait=true, 60s)` 无输出，收到“不要重复相同调用”提醒。

**根因**：`df.sh` 把构建输出缓冲到最后，轮询本就不会有中间日志；继续同参数等待没有信息增益。

**修复**：无输出后改为服务器侧 `ps` / `docker images` / `git log` 检查；
或换更长间隔。收到重复调用提醒立即停止该链。

**已固化**：交接文档 §6 部署坑。

### 3.4 默认“本地预览”而不是先问预览方式

**现象**：用户说“帮我拉起本地预览环境”，随后立即撤回“不要本地，合并进去看部署效果”。

**根因**：把“看观感”默认理解成本地开发服务器；没有先确认用户要本地还是已部署环境。

**修复**：UI 验收默认先给部署预览入口，或先问一句“本地预览还是部署后看？”；
用户已明确“不要在我本地启动”后，不再主动起本地服务。

**已固化**：交接文档 §5，明确下会话不要起本地预览。

## 5. 本次做对、值得保留的做法

1. **设计 → 计划 → 实现 → 验收**四段式没有被跳过；ASReview 设计分三节让用户确认，避免实现后返工。
2. **子代理按 Task 独立提交**，Lead 逐任务审查 + 回归；缺口在合并前修复。
3. **部署前先确认服务器 main 与本地 main 的祖先关系**，没有用 `reset --hard` 丢掉服务器 revert 历史。
4. **没有新迁移就不硬造迁移**；用 `alembic current/heads` 证明一致。
5. **UI 完成标准**执行到位：Playwright 登录真实环境、截图、读图、确认 4 个名次，而不是只看单测。
6. **边界测试补齐**：跨筛选者 include/exclude 冲突、API URL 编码、阶段过滤关闭排序，均在部署前补上。
