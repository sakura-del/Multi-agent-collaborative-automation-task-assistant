## 变更摘要（Issue #28 BYOK 收尾）

- **凭据级「失败回退平台模型」开关**（默认关）：`allow_platform_fallback`。
  开启后有两条回退路径——绑定期凭据被停用 → 直接改绑平台；调用期
  **401/402/403** → `PlatformFallbackClient`（`app/llm/fallback.py`）首次失败即
  粘住平台。**429/超时/5xx 永不回退**（限流是抖动，静默烧平台钱比任务失败更糟）；
  平台未配置时不落标注、直接失败。
- **回退的账**：`task.actual_provider/actual_model` 如实标注实际模型（界面提示
  「已回退平台模型 · 本次消耗平台额度」）；`task.fallback_token_base` 记回退时刻
  的已用量基线，结算**只退平台实际消耗**（ESTIMATED − (总用量 − 基线)），
  BYOK 阶段花的用户自己的钱不进退款；篇数在回退时补扣（提交时已按平台扣过则不重复）。
- **生成能力探测 + planner 门禁**：`POST /llm-credentials/{id}/probe-generation`
  用用户 key 发一次 max_tokens=64 的最小结构化输出请求（约 100 token，UI 已注明），
  结果写进 `capabilities.json_mode`；`PUT /llm-routing` 保存 planner 路由时校验
  该能力，未通过 → 400 并提示先探测或换凭据。key 被拒（401/402/403）计入凭据失败
  计数；「能聊天但格式不对」只记 last_error 不计数。

## 已知取舍

- 回退**只发生在运行中**；绑定期凭据被删除（外键 SET NULL 且无记录可读开关）
  仍按原语义失败——用户偏好无法从快照恢复，静默回退会让用户以为 key 还在用。
- 篇数补扣失败（`PLAN_QUOTA_EXCEEDED` 等）**不阻断回退**：调用已经发生，
  记 warning 从 `actual_provider` 反查补账。
- 探测不做定时自动跑：消耗用户 key 且成本不可控，只保留手动按钮。
